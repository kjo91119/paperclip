# 2026-04-04 오피스 메시지 독 교차검증 지시서

## 1. 목적

이번 변경은 기존 `2D 오피스` 화면 아래에 `오피스 메시지 독`을 추가해,
보드 운영자가 에이전트에게 바로 업무를 보내거나 현재 작업에 코멘트를 붙일 수 있게 하는 작업이다.

검증 목표:

- 오피스 화면 아래 메시지 독이 정상 표시되는지 확인
- 선택한 에이전트/프로젝트 기준으로 대상이 올바르게 바뀌는지 확인
- `현재 작업에 코멘트`와 `새 이슈로 보내기`가 각각 정확한 대상에 반영되는지 확인
- 프로젝트 경로/저장소 정보가 메시지 컨텍스트에 자연스럽게 포함되는지 확인
- 마케팅 템플릿과 편의 버튼이 실제 업무 흐름에 도움이 되는지 확인

## 2. 검증 범위

이번 교차검증 범위에 포함되는 파일:

- `ui/src/pages/OfficeView.tsx`
- `ui/src/pages/officeViewModel.ts`
- `ui/src/pages/OfficeView.model.test.ts`

이번 교차검증 범위에 포함되지 않는 것:

- 기존 2D 오피스 라우트/사이드바 추가 자체
- 로컬 `.cmd` 실행기나 바탕화면 바로가기
- Paperclip 외부 프로젝트 자체의 품질 평가

## 3. 변경 요약

이번 변경으로 추가된 사용자 흐름:

1. 오피스 화면 아래 `오피스 메시지 독` 표시
2. 에이전트 빠른 선택
3. 프로젝트 선택
4. 경로 직접 입력 또는 프로젝트 경로 자동 삽입
5. 마케팅 템플릿 버튼으로 제목/본문 자동 채우기
6. 선택한 에이전트의 현재 작업이 있으면 그 이슈에 코멘트 추가
7. 현재 작업이 없거나 새 작업으로 보내고 싶으면 새 이슈 생성
8. 마지막으로 보낸 이슈 바로가기 제공

추가된 편의 기능:

- 경로 복사
- 프로젝트 연결 상태 힌트
- 선택한 현재 코멘트 대상 이슈 미리보기
- 회사별 드래프트 자동 저장

## 4. 사전 준비

저장소 루트에서 아래를 준비한다.

```sh
pnpm install

```

http://127.0.0.1:3100/STU/office

STU 회사가 없다면 현재 로컬 환경의 실제 회사 프리픽스를 사용한다.

## 6. 수동 교차검증 절차

### A. 기본 표시 확인

1. `/<companyPrefix>/office`로 들어간다.
2. 기존 2D 오피스 장면 아래에 `오피스 메시지 독` 섹션이 보이는지 확인한다.
3. 섹션 안에 아래 요소가 보이는지 본다.

- 대상 에이전트 선택
- 대상 프로젝트 선택
- 새 이슈 제목 입력
- 빠른 템플릿 버튼
- 참고 경로 입력
- 메시지 본문 입력
- `현재 작업에 코멘트`
- `새 이슈로 보내기`

기대 결과:

- 메시지 독이 장면과 분리된 별도 작업 영역으로 보여야 한다.
- 버튼이나 입력창이 겹치거나 잘리면 안 된다.

### B. 에이전트 선택 동작

1. 에이전트 칩을 여러 개 바꿔가며 선택한다.
2. 우측 `선택한 에이전트` 카드가 즉시 바뀌는지 확인한다.
3. 에이전트 현재 구역/현재 작업 안내가 선택한 대상과 맞는지 본다.

기대 결과:

- 선택 상태가 바로 반영되어야 한다.
- 이전 에이전트의 작업 내용이 남아 있으면 안 된다.

### C. 프로젝트 선택 동작

1. 프로젝트가 있다면 프로젝트를 바꿔가며 선택한다.
2. `프로젝트 컨텍스트` 카드의 로컬 폴더/저장소 정보가 바뀌는지 확인한다.
3. `프로젝트 경로 삽입` 또는 `프로젝트 경로 사용` 버튼이 기대대로 동작하는지 확인한다.

기대 결과:

- 프로젝트 선택과 컨텍스트가 일치해야 한다.
- 프로젝트가 없는 경우 `프로젝트 만들기` 흐름이 보이는 것이 정상이다.

### D. 템플릿 버튼 확인

1. 아래 템플릿 버튼을 하나씩 눌러본다.

- `홍보 전략`
- `콘텐츠 아이디어`
- `첫 실험안`
- `경쟁사 비교`

2. 제목과 본문이 채워지는지 확인한다.
3. 프로젝트를 선택한 상태라면 프로젝트 이름이 템플릿 문구에 자연스럽게 반영되는지 본다.

기대 결과:

- 제목과 본문이 동시에 채워져야 한다.
- 깨진 문자열, 잘못 닫힌 문장, 비어 있는 텍스트가 있으면 안 된다.

### E. 경로 입력/복사 확인

1. 참고 경로에 임의 경로를 넣는다.
2. `경로 복사`를 눌러 복사되는지 확인한다.
3. 프로젝트에 로컬 경로가 연결돼 있으면 `프로젝트 경로 사용`이 그 경로를 입력칸에 채우는지 본다.

실사용 예시:

```text
C:\Users\frog5\Desktop\사이트만들기\클로드1\projects\02-jangsatok
```

기대 결과:

- 직접 입력한 경로도 유지되어야 한다.
- 프로젝트 경로 자동 채우기와 수동 입력이 서로 충돌하면 안 된다.

### F. 현재 작업에 코멘트

1. 어떤 에이전트가 현재 열려 있는 이슈를 갖고 있는 상태를 고른다.
2. 메시지 본문에 짧은 지시를 입력한다.
3. `현재 작업에 코멘트`를 누른다.
4. 성공 토스트가 뜨는지 확인한다.
5. 연결된 이슈로 들어가 실제 댓글이 추가됐는지 확인한다.
6. 댓글 본문에 아래 컨텍스트가 함께 포함됐는지 확인한다.

- 프로젝트명
- 로컬 경로
- 저장소 URL

기대 결과:

- 선택한 에이전트의 현재 작업 중 올바른 이슈에 댓글이 붙어야 한다.
- 전혀 다른 프로젝트 이슈에 잘못 붙으면 반려다.

### G. 새 이슈로 보내기

1. 현재 작업이 없거나, 일부러 새 작업으로 보내고 싶은 상태를 고른다.
2. 제목/본문을 입력한다.
3. `새 이슈로 보내기`를 누른다.
4. 성공 토스트와 `마지막 이슈 열기`가 나타나는지 확인한다.
5. 새 이슈를 열어 아래를 확인한다.

- assignee가 선택한 에이전트인지
- project가 선택한 프로젝트인지
- description에 작성한 본문과 컨텍스트가 들어갔는지

기대 결과:

- 새 이슈는 선택한 에이전트에게 할당되어야 한다.
- 프로젝트를 골랐다면 그 프로젝트 아래 생성되어야 한다.

### H. 장사톡 실사용 시나리오

가능하면 아래 실제 시나리오를 한 번 따라간다.

1. `장사톡` 프로젝트를 선택하거나, 아직 없다면 참고 경로에 아래 경로를 직접 넣는다.

```text
C:\Users\frog5\Desktop\사이트만들기\클로드1\projects\02-jangsatok
```

2. `CMO`를 선택한다.
3. `홍보 전략` 템플릿을 누른다.
4. 필요한 부분을 조금만 수정한 뒤 `새 이슈로 보내기`를 누른다.
5. 생성된 이슈 본문에 `장사톡` 관련 경로와 문맥이 잘 들어갔는지 확인한다.
6. 이어서 같은 이슈 또는 다른 이슈에서 `CEO`에게 시장 검증/우선순위 질문도 보내본다.

기대 결과:

- 이 기능이 단순 데모가 아니라 실제 협업 시작점으로 쓸 수 있어야 한다.
- `장사톡` 같은 외부 프로젝트를 Paperclip 안 대화 맥락으로 끌어오는 흐름이 자연스러워야 한다.

### I. 드래프트 유지 확인

1. 제목/본문/경로를 일부 입력한다.
2. 다른 페이지로 갔다가 다시 오피스로 돌아온다.
3. 입력 내용이 유지되는지 확인한다.

기대 결과:

- 회사별 초안이 유지되어야 한다.
- 완전히 다른 회사로 바꾸면 초안이 섞이지 않는 것이 바람직하다.

### J. 반응형 확인

1. 데스크톱 폭에서 메시지 독 레이아웃이 무너지지 않는지 본다.
2. 좁은 화면에서 입력창, 버튼, 선택 칩이 최소한 사용 가능한지 확인한다.
3. 특히 하단 버튼 두 개가 잘리지 않는지 본다.

기대 결과:

- 모바일에서 완벽히 동일할 필요는 없지만, 입력/전송이 가능해야 한다.

## 7. 반려 기준

아래 중 하나라도 확인되면 커밋 전 수정이 우선이다.

- 메시지 독이 렌더링되지 않음
- 선택한 에이전트/프로젝트와 실제 전송 대상이 불일치함
- `현재 작업에 코멘트`가 엉뚱한 이슈에 붙음
- `새 이슈로 보내기`가 선택한 에이전트에게 할당되지 않음
- 경로/프로젝트 컨텍스트가 본문에 반영되지 않음
- 템플릿 버튼이 제목/본문을 비정상적으로 채움
- 오피스 페이지 자체 사용성을 해칠 정도로 레이아웃이 깨짐

## 8. 승인 가능 기준

- 에이전트/프로젝트 선택 흐름이 자연스럽다

- `장사톡` 같은 실제 프로젝트 협업 시나리오로 써도 흐름이 납득 가능하다
