# 2026-04-04 오피스 전체회의/경로 변환 교차검증 지시서

## 1. 목적

이번 변경은 기존 `오피스 메시지 독`을 확장해 아래 흐름을 추가한 작업이다.

- 상단 `메시지 독 바로가기` 배너
- `개별 지시`와 `전체회의` 모드 전환
- Windows 경로를 WSL 경로로 자동 정규화
- `WSL 경로 복사` / `Windows 경로 복사`
- 프로젝트 컨텍스트와 수동 참고 경로 불일치 경고

검증 목표:

- 오피스 상단에서 메시지 독 진입이 쉬워졌는지 확인
- `전체회의` 모드가 단일 담당자 모델을 깨지 않고 자연스럽게 동작하는지 확인
- Windows 경로를 붙여넣어도 실제 전송 컨텍스트가 WSL 경로로 정리되는지 확인
- 프로젝트 선택, 자동 경로, 수동 경로, 경고 배지가 서로 충돌하지 않는지 확인
- `장사톡` 같은 실제 프로젝트를 기준으로 바로 업무를 만들 수 있는지 확인

## 2. 검증 범위

이번 교차검증 범위에 포함되는 파일:

- `ui/src/pages/OfficeView.tsx`
- `ui/src/pages/officeViewModel.ts`
- `ui/src/pages/OfficeView.model.test.ts`

이번 교차검증 범위에 포함되지 않는 것:

- 서버의 이슈/댓글 데이터 모델 자체 변경
- `.cmd` 실행기나 바탕화면 바로가기
- `장사톡` 코드베이스 자체의 품질 평가

## 3. 변경 요약

이번 변경으로 추가되거나 강화된 사용자 흐름:

1. 오피스 상단 `메시지 독 바로가기` 배너 표시
2. `메시지 독 열기` 클릭 시 하단 메시지 독으로 이동
3. `작업 방식`에서 `개별 지시` / `전체회의` 전환
4. `전체회의`에서 진행자 1명 + 참가자 여러 명 선택
5. Windows 경로 입력 시 내부적으로 WSL 경로로 정규화
6. 정규화된 경로를 WSL/Windows 형식으로 각각 복사
7. 프로젝트 경로 자동 동기화와 수동 경로 사용을 구분
8. 선택 프로젝트 경로와 수동 경로가 다를 때 경고 표시

중요한 구현 제약:

- 현재 버전의 `전체회의`는 실제 다중 assignee나 시스템 차원의 회의 초대 기능이 아니다.
- 진행자 1명에게만 새 이슈를 할당하고 wakeup 한다.
- 나머지 참가자는 새 이슈 본문에 멘션 텍스트로만 함께 기록된다.

## 6. 수동 교차검증 절차

### A. 상단 바로가기 확인

1. `/<companyPrefix>/office`로 들어간다.
2. 상단에 `메시지 독 바로가기` 배너가 보이는지 확인한다.
3. `메시지 독 열기`를 누른다.

기대 결과:

- 상단 배너가 오피스 상단에 붙어 보여야 한다.
- 버튼을 누르면 `오피스 메시지 독`으로 스크롤 이동해야 한다.
- 가능하면 본문 입력칸에 포커스가 가는 것이 좋다.

### B. 프로젝트 선택 확인

1. `대상 프로젝트` 드롭다운을 연다.
2. `장사톡`이 보이는지 확인한다.
3. `장사톡`을 선택한다.
4. 우측 `프로젝트 컨텍스트` 카드가 바뀌는지 본다.

기대 결과:

- `장사톡`이 보이면 선택 가능해야 한다.
- 선택 후 로컬 폴더/저장소 정보가 `장사톡` 기준으로 바뀌어야 한다.

참고:

- 로컬 인스턴스에 `장사톡`이 아직 없으면, 이번 판정은 `경로 수동 입력 시나리오`로 대신 검증해도 된다.

### C. Windows 경로 정규화 확인

1. `대상 프로젝트`를 `장사톡`으로 두거나, 프로젝트 없이 진행해도 된다.
2. `참고 경로`에 아래 Windows 경로를 붙여넣는다.

```text
C:\Users\frog5\Desktop\사이트만들기\클로드1\projects\02-jangsatok
```

3. 입력 직후 경로가 WSL 형식으로 정규화되는지 본다.
4. `WSL 경로 복사`를 눌러 복사 가능한지 확인한다.
5. `Windows 경로 복사`도 가능한지 확인한다.

기대 결과:

- 내부적으로는 `/mnt/c/.../02-jangsatok` 형태로 정리되어야 한다.
- Windows 경로를 넣었다고 경고가 뜨면 안 된다.
- 복사 버튼은 가능한 형식만 활성화되어야 한다.

### D. 프로젝트 경로 자동 동기화 확인

1. `장사톡` 프로젝트를 고른다.
2. `프로젝트 경로 사용`을 누른다.
3. 프로젝트를 다른 항목으로 바꾸거나 해제한다.

기대 결과:

- `project` 모드에서는 참고 경로가 선택 프로젝트 경로와 자동 동기화되어야 한다.
- 프로젝트를 해제하면 자동 경로는 비워지거나 새 프로젝트 경로로 갱신되어야 한다.
- 이전 프로젝트 경로가 stale 상태로 남아 있으면 반려다.

### E. 수동 경로 경고 확인

1. `장사톡` 프로젝트를 선택한다.
2. `참고 경로`에 장사톡과 다른 임의 경로를 직접 넣는다.
3. 수동 입력 상태를 유지한다.

예시:

```text
C:\Users\frog5\Desktop\other-project
```

기대 결과:

- 선택 프로젝트의 로컬 폴더와 다른 경로라고 경고가 떠야 한다.
- 안내 문구가 “수동 입력한 경로가 우선 전송된다”는 의미로 보여야 한다.

### F. 개별 지시 흐름 확인

1. `작업 방식`을 `개별 지시`로 둔다.
2. 에이전트 하나를 선택한다.
3. `대상 프로젝트`를 `장사톡`으로 고른다.
4. 본문을 입력하고 `새 이슈로 보내기`를 누른다.

예시 본문:

```text
장사톡 프로젝트를 보고 첫 홍보 전략, 타깃 고객, 빠르게 실험할 채널을 정리해주세요.
```

기대 결과:

- 새 이슈가 선택한 에이전트에게 생성되어야 한다.
- 프로젝트를 선택했다면 이슈 본문에 프로젝트명은 포함되어야 한다.
- 로컬 경로와 저장소 URL은 현재 프로젝트나 입력값에 실제 값이 있을 때만 포함되면 된다.
- 참고 경로는 WSL 기준 경로로 들어가야 한다.

### G. 전체회의 흐름 확인

1. `작업 방식`을 `전체회의`로 바꾼다.
2. `회의 진행자`를 `CEO`, `CMO`, 또는 원하는 인원으로 고른다.
3. 다른 에이전트 1명 이상을 참가자로 선택한다.
4. `대상 프로젝트`를 `장사톡`으로 둔다.
5. 본문을 입력하고 `회의 이슈 만들기`를 누른다.

예시 본문:

```text
장사톡 프로젝트를 기준으로 첫 홍보 전략, 기술 보완 포인트, 사업성 우선순위를 함께 정리해주세요.
```

기대 결과:

- 진행자를 포함해 2명 미만이면 버튼이 비활성화되어야 한다.
- 생성된 이슈는 진행자 1명에게만 assignee로 들어가야 한다.
- 본문에는 `회의 형식`, `진행자`, `참가자` 정보가 멘션 텍스트와 함께 들어가야 한다.
- 우측 카드도 `회의 초대 상태` 기준으로 바뀌어야 한다.

### H. 장사톡 실사용 시나리오

가능하면 아래 실제 시나리오를 따라간다.

1. `대상 프로젝트`: `장사톡`
2. `작업 방식`: `전체회의`
3. `회의 진행자`: `CEO`
4. `회의 참가자`: `CTO`, `CMO`
5. 본문:

```text
장사톡 프로젝트를 보고 첫 홍보 전략, 기술 보완 우선순위, 첫 고객 검증 방식을 같이 정리해주세요.
원하는 결과:
- 핵심 타깃 고객 3개
- 첫 홍보 채널 5개
- CTO 기준 기술 리스크
- CEO 기준 사업성 판단 포인트
```

6. `회의 이슈 만들기`를 누른다.

기대 결과:

- 이 흐름만으로 진행자 중심의 회의 이슈 초안과 참가자 컨텍스트를 만들 수 있어야 한다.
- `장사톡`이라는 실제 외부 프로젝트가 Paperclip 안 컨텍스트로 자연스럽게 연결되어야 한다.

### I. 회귀 확인

1. 다시 `개별 지시`로 돌아간다.
2. 기존처럼 `현재 작업에 코멘트`가 보이는지 확인한다.
3. `전체회의`에서는 이 버튼이 숨겨지는지 확인한다.

기대 결과:

- `개별 지시`와 `전체회의`의 행동이 섞이면 안 된다.
- 모드에 따라 버튼과 우측 설명 카드가 같이 바뀌어야 한다.

## 7. 반려 기준

아래 중 하나라도 보이면 커밋 전 수정이 우선이다.

- `메시지 독 바로가기`가 보이지 않음
- `장사톡` 프로젝트 선택과 실제 컨텍스트가 어긋남
- Windows 경로가 잘못 정규화되거나 그대로 잘못 전송됨
- 프로젝트 경로와 수동 경로가 stale 상태로 섞임
- `전체회의`에서 진행자를 포함해 2명 미만인데도 이슈 생성 가능
- `전체회의`가 다중 assignee처럼 오해되게 동작함
- 생성된 이슈 본문에 진행자/참가자/프로젝트 컨텍스트가 빠짐
- 기존 `개별 지시` 흐름이 회귀함

## 8. 승인 가능 기준

아래가 모두 맞으면 커밋 후 푸시 단계로 넘어가도 된다.

- 메시지 독 상단 진입이 자연스럽다
- `장사톡` 같은 실제 프로젝트를 선택해 바로 쓸 수 있다
- Windows 경로 입력이 WSL 기준으로 안정적으로 정리된다
- `전체회의`가 현재 V1 제약 안에서 충분히 납득 가능하게 동작한다
- 자동 검증에 새 회귀가 없다
